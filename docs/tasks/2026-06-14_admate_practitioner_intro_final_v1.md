# AdMate 파일럿 소개
## 반복 확인은 줄이고, 판단은 남깁니다

이 문서는 AdMate 초기 파일럿에 참여하는 특정 팀과 소수 실무자를 위한 소개 문서입니다.
AdMate는 사람을 대체하는 도구가 아닙니다. 캠페인 운영에서 반복되는 정책 확인, 세팅 검수, 캡처 준비, 예상 범위 확인, 이상 신호 점검의 부담을 줄이고, 실무자가 더 중요한 판단에 집중할 수 있도록 돕는 업무 파트너입니다.

파일럿은 완성된 시스템을 전체 공개하는 과정이 아닙니다.
실제 업무 흐름 안에서 어떤 확인이 줄어드는지, 어떤 결과는 사람이 다시 봐야 하는지, 어떤 판단과 예외 처리를 다음 운영 기준으로 남길 수 있는지 함께 확인하는 과정입니다.

실제 플랫폼 캡처는 이 문서에 삽입하지 않습니다.
이후 캡처를 넣을 때도 모든 화면은 민감 정보가 제거된 샘플 또는 익명화 화면만 사용합니다.

## 1. 이 문서가 필요한 이유

캠페인 운영에는 매번 반복되는 확인이 있습니다.
정책 문구를 다시 찾고, 미디어믹스와 매체 설정을 대조하고, 캡처 누락을 확인하고, 성과 흐름이 평소와 다른지 살펴보고, 다음 제안을 위해 이전 기준을 다시 찾아봅니다.

이 확인들은 중요하지만, 매번 사람이 처음부터 끝까지 반복하기에는 시간이 많이 들고 놓치기 쉬운 지점도 생깁니다.
AdMate 파일럿은 이 반복 확인을 한 번에 없애겠다는 약속이 아니라, 실제 업무에서 줄일 수 있는 부분과 사람이 계속 판단해야 하는 부분을 차분히 나누는 과정입니다.

이 문서는 파일럿 참여자가 다음을 이해하도록 돕기 위해 작성되었습니다.

| 질문 | 이 문서에서 확인할 내용 |
|---|---|
| 내 업무에서 무엇이 달라지나요? | 정책 확인, 세팅 검수, 캡처, 예상 범위 확인, 운영 신호 점검이 어떻게 정리되는지 봅니다. |
| AI가 내 판단을 대신하나요? | 아닙니다. AdMate는 근거와 후보를 보여주고, 최종 판단과 예외 승인은 사람이 합니다. |
| 내 피드백은 어디에 쓰이나요? | 좋은 판단과 반복되는 예외는 승인된 절차를 거쳐 다음 운영 기준 후보가 됩니다. |
| 무엇을 조심해야 하나요? | 민감 정보는 문서, 캡처, 질문, 피드백에 그대로 넣지 않습니다. |

## 2. 한 장 요약

AdMate는 캠페인 운영의 반복 확인을 줄이고, 실무자의 판단을 지식 근거로 남겨 함께 진화하는 AI 기반 업무 흐름입니다.

| 핵심 | 실무자에게 의미하는 것 |
|---|---|
| 파일럿 대상 | 전체 공개가 아니라 특정 팀과 소수 사용자를 대상으로 먼저 확인합니다. |
| AdMate의 역할 | 정책, 세팅, 캡처, 예상 범위, 운영 신호를 먼저 정리해 보여줍니다. |
| 실무자의 역할 | 결과와 근거를 확인하고 승인, 반려, 예외 설명, 피드백을 남깁니다. |
| 판단의 의미 | 올바른 판단은 개인 기억에만 남지 않고, 검토 후 다음 운영 기준 후보가 됩니다. |
| 안전 원칙 | 실제 광고주명, 계정명, 캠페인명, 개인정보, 원본 URL, 토큰, 원본 리포트 행은 넣지 않습니다. |
| 피드백 방식 | 불편한 흐름과 개선 제안은 익명 피드백 보드에 안전하게 남길 수 있습니다. |

AdMate는 다음 다섯 영역으로 이해하면 쉽습니다.

| 영역 | 한 줄 역할 | 실무자가 보는 장면 |
|---|---|---|
| Compass | 정책과 가이드의 방향을 빠르게 확인합니다. | 질문, 답변, 출처, 근거 상태 |
| Sentinel | 세팅 사고를 줄이고 운영 이상 신호를 보여줍니다. | 사전 검수, 상태 요약, 확인 필요 항목 |
| Lens | 캡처와 증빙 준비를 작업 목록으로 정리합니다. | 캡처 요청, 진행 상태, 실패 사유, 결과 확인 |
| Foresight | 다음 캠페인의 예상 범위와 근거를 봅니다. | 입력 조건, 예상 범위, 비교 카드 |
| 운영 기록과 기준 관리 | 판단, 승인, 예외, 피드백을 기준 후보로 정리합니다. | 권한, 기록, 승인 상태, 기준 후보 |

>
> 넣을 화면: Compass, Sentinel, Lens, Foresight, 운영 기록과 기준 관리 영역이 하나의 캠페인 운영 흐름 안에서 연결되는 요약 화면.
>
> 제거할 민감정보: 실제 광고주명, 브랜드명, 계정명, 캠페인명, 담당자명, 이메일, 원본 URL, 토큰, 원본 리포트 행, production 콘솔의 민감 화면.

## 3. 캠페인 운영 흐름에서 AdMate가 돕는 위치

큰 흐름은 단순합니다.
AdMate가 먼저 확인할 항목과 근거를 정리하고, 실무자가 판단하며, 필요한 경우 그 판단을 다음 기준 후보로 남깁니다.

| 캠페인 단계 | 실무자가 자주 하는 일 | AdMate가 돕는 방식 |
|---|---|---|
| 기획 전 | 정책 제한, 운영 기준, 과거 조건을 확인합니다. | Compass와 Foresight가 확인할 근거와 예상 범위를 정리합니다. |
| 시작 전 | 미디어믹스와 매체 세팅이 맞는지 대조합니다. | Sentinel이 차이, 누락, 확인 필요 항목을 보여줍니다. |
| 운영 중 | 성과나 상태가 평소와 다른지 확인합니다. | Sentinel이 이상 신호와 우선 점검 항목을 요약합니다. |
| 증빙 준비 | 캡처 누락, 실패, 재요청 여부를 확인합니다. | Lens가 캡처 작업과 결과를 한곳에서 관리합니다. |
| 기준 정리 | 판단 이유와 예외 처리 맥락을 남깁니다. | 운영 기록과 기준 관리 영역이 승인된 기록을 기준 후보로 정리합니다. |

AdMate가 보여주는 결과는 판단의 출발점입니다.
정책 리스크, 예산 영향, 고객 영향, 캠페인 적용처럼 중요한 결정은 반드시 지정된 실무자와 승인 절차를 거쳐야 합니다.

## 4. 플랫폼별 소개

### 4.1 Compass: 정책 확인을 빠르게

Compass는 광고 정책, 운영 가이드, 내부 기준을 찾는 시간을 줄이고 답변의 근거를 함께 확인하게 돕는 영역입니다.
답변만 보는 것이 아니라 출처, 근거 상태, 적용 범위를 같이 확인하는 방식으로 사용합니다.

| 상황 | Compass에서 확인할 것 |
|---|---|
| 정책 문구가 기억나지 않을 때 | 관련 기준의 요약과 출처 문서를 확인합니다. |
| 특정 표현이나 소재가 가능한지 헷갈릴 때 | 제한 조건, 예외 여부, 추가 확인 필요 항목을 봅니다. |
| 고객이나 내부 팀에 근거를 설명해야 할 때 | 답변의 출처와 근거 상태를 함께 확인합니다. |
| 기존 가이드가 최신인지 확인해야 할 때 | 참고 문서와 적용 범위를 확인합니다. |

| 실무자가 볼 항목 | 보는 이유 |
|---|---|
| 답변 요약 | 질문에 대한 1차 방향을 빠르게 잡습니다. |
| 출처 | 답변이 어떤 정책이나 가이드에 근거하는지 확인합니다. |
| 근거 상태 | 확실한 기준인지, 추가 확인이 필요한지 구분합니다. |
| 적용 범위 | 모든 캠페인에 적용되는지, 특정 조건에서만 적용되는지 봅니다. |

Compass의 답변은 최종 승인이나 법적 판단을 대신하지 않습니다.
정책상 애매하거나 고객 영향이 큰 사안은 출처와 조건을 확인한 뒤 지정된 승인 절차를 거쳐야 합니다.
질문에는 실제 광고주명, 계정명, 캠페인명, 원본 URL을 그대로 넣지 않습니다.

> [CAPTURE_PLACEHOLDER: Compass / answer-source-panel / redacted]
>
> 넣을 화면: 사용자가 광고 정책 질문을 입력하고, 답변 카드와 출처 패널이 함께 보이는 장면.
>
> 제거할 민감정보: 실제 광고주명, 브랜드명, 계정명, 캠페인명, 내부 민감 문서명, 원본 URL, 담당자 이름, 이메일, 원본 소재 URL.

### 4.2 Sentinel: 세팅 사고를 막고 운영 이상을 감지

Sentinel은 캠페인 시작 전 세팅 차이를 확인하고, 운영 중 놓치기 쉬운 이상 신호를 먼저 보여주는 영역입니다.
캠페인을 임의로 수정하지 않으며, 실제 적용과 예외 승인은 사람이 근거를 확인한 뒤 결정합니다.

| 상황 | Sentinel에서 확인할 것 |
|---|---|
| 캠페인 시작 전 | 미디어믹스와 매체 설정의 차이, 누락, 확인 필요 항목을 봅니다. |
| 시작 가능 여부를 확인할 때 | 현재 상태가 통과, 확인 필요, 보류 중 어디에 가까운지 확인합니다. |
| 운영 중 성과나 상태가 평소와 다를 때 | 이상 신호, 영향 범위, 우선 확인할 항목을 봅니다. |
| 예외 처리가 필요할 때 | 어떤 이유로 예외가 필요한지 근거와 기록을 남깁니다. |

| 실무자가 볼 항목 | 보는 이유 |
|---|---|
| 차이 항목 | 설정값이 계획과 다르거나 빠진 부분을 확인합니다. |
| 상태 요약 | 바로 진행 가능한지, 추가 확인이 필요한지 판단합니다. |
| 근거 | 왜 확인이 필요한지 설명할 수 있는 정보를 봅니다. |
| 조치 기록 | 승인, 반려, 예외 처리의 이유가 남는지 확인합니다. |

Sentinel 알림이 많거나 적다고 느껴지는 지점은 파일럿 피드백으로 남겨 주세요.
어떤 신호가 실무에 도움이 되고 어떤 신호가 부담이 되는지 확인하는 것이 이번 파일럿의 중요한 목적입니다.

> [CAPTURE_PLACEHOLDER: Sentinel / prelaunch-workbench-status-panel / redacted]
>
> 넣을 화면: 미디어믹스 입력, 매체 설정 대조, 확인 필요 항목, 시작 가능 상태, 조치 기록 영역이 함께 보이는 화면.
>
> 제거할 민감정보: 실제 캠페인명, 계정명, 광고주명, 매체 계정 ID, 원본 매체 URL, 랜딩 원본 URL, 원본 리포트 행, production 콘솔 민감 화면.

### 4.3 Lens: 캡처와 증빙을 정리

Lens는 광고 캡처와 증빙 준비를 작업 목록으로 관리해 누락, 실패, 재요청 확인 부담을 줄이는 영역입니다.
어떤 소재를 어떤 지면에서 캡처해야 하는지, 진행 상태가 무엇인지, 실패한 작업은 왜 실패했는지 한곳에서 확인하는 것을 목표로 합니다.

| 상황 | Lens에서 확인할 것 |
|---|---|
| 캡처 작업을 요청할 때 | 어떤 소재, 지면, 형식의 캡처가 필요한지 정리합니다. |
| 진행 상황을 확인할 때 | 진행 중, 완료, 실패, 재요청 필요 상태를 봅니다. |
| 캡처가 실패했을 때 | 실패 사유와 다음 조치를 확인합니다. |
| 증빙을 준비할 때 | 사용할 수 있는 결과물과 누락 여부를 확인합니다. |

| 실무자가 볼 항목 | 보는 이유 |
|---|---|
| 요청 조건 | 필요한 캡처가 정확히 요청되었는지 봅니다. |
| 작업 상태 | 완료와 실패를 구분하고 누락을 줄입니다. |
| 실패 사유 | 재요청이 필요한지, 조건을 바꿔야 하는지 판단합니다. |
| 결과물 | 증빙에 사용할 수 있는 상태인지 확인합니다. |

캡처 결과에는 민감 정보가 포함될 수 있습니다.
원본 캡처를 문서, 메신저, 피드백 보드에 그대로 올리지 말고, 필요한 경우 민감 정보가 제거된 화면만 사용합니다.
캡처 실패는 개인의 실수가 아니라 작업 조건을 다시 확인해야 한다는 신호로 다룹니다.

> [CAPTURE_PLACEHOLDER: Lens / capture-workbench / redacted]
>
> 넣을 화면: 캡처 요청 생성, 작업 목록, 실패 또는 재요청 상태, 결과 확인 영역이 함께 보이는 화면.
>
> 제거할 민감정보: 실제 브랜드명, 광고주명, 캠페인명, 소재 원본 URL, 계정 식별자, 담당자명, 내부 캡처 원본, production 콘솔 민감 화면.

### 4.4 Foresight: 다음 캠페인의 예상 범위와 근거 보기

Foresight는 예산, 기간, 타겟 조건에 따른 예상 성과를 단일 확정값이 아니라 범위와 근거로 확인하는 영역입니다.
기획 단계에서 더 나은 질문과 비교를 돕는 참고 정보로 사용하며, 실제 성과를 보장하지 않습니다.

| 상황 | Foresight에서 확인할 것 |
|---|---|
| 제안 전 가설을 잡을 때 | 예산과 기간에 따른 예상 범위를 확인합니다. |
| 여러 조건을 비교할 때 | 타겟, 목표 KPI, 운영 조건별 차이를 봅니다. |
| 내부 논의 자료가 필요할 때 | 예측 결과와 근거를 함께 정리합니다. |
| 다음 캠페인 기준을 세울 때 | 이전 결과와 새 조건을 비교해 가설을 다듬습니다. |

| 실무자가 볼 항목 | 보는 이유 |
|---|---|
| 입력 조건 | 예산, 기간, 타겟, 목표 KPI가 맞는지 확인합니다. |
| 예상 범위 | 하나의 숫자보다 가능한 범위와 변화 방향을 봅니다. |
| 근거 상태 | 어떤 데이터와 조건에 기반한 결과인지 확인합니다. |
| 비교 결과 | 조건을 바꿨을 때 차이가 실무적으로 의미 있는지 봅니다. |

Foresight 결과는 실제 성과를 확정하지 않습니다.
최종 제안과 운영 판단은 고객 상황, 예산 조건, 정책 리스크, 실무 맥락을 함께 본 뒤 사람이 결정합니다.

> [CAPTURE_PLACEHOLDER: Foresight / simulator-result-range-evidence / redacted]
>
> 넣을 화면: 예산, 기간, 타겟 조건을 입력한 뒤 예상 성과 범위와 근거 카드가 표시되는 장면.
>
> 제거할 민감정보: 실제 고객 데이터, 광고주명, 브랜드명, 캠페인명, 원본 리포트 행, 원본 엑셀 행, 원본 API 응답, 계정 식별자.

### 4.5 운영 기록과 기준 관리: 판단을 다음 기준으로 남기기

운영 기록과 기준 관리 영역은 실무자의 판단, 승인, 예외 처리, 피드백을 안전하게 남기고 다음 운영 기준 후보로 정리하는 공통 영역입니다.
이 영역의 핵심 메시지는 단순합니다.

```text
올바른 판단을 지식 근거로 남기고, 검토된 기준으로 함께 진화합니다.
```

모든 행동이 자동으로 기준에 반영되는 것은 아닙니다.
중요한 판단과 반복적으로 유용한 기준 후보는 승인된 검토 절차를 거친 뒤에만 운영 기준으로 다룹니다.

| 상황 | 확인할 것 |
|---|---|
| 예외 승인이 필요할 때 | 누가, 어떤 근거로, 어떤 범위에서 승인했는지 남깁니다. |
| 반복되는 판단이 있을 때 | 다음에도 참고할 수 있는 기준 후보로 정리합니다. |
| 권한 확인이 필요할 때 | 내가 볼 수 있는 범위와 처리할 수 있는 일을 확인합니다. |
| 피드백을 검토할 때 | 개선 요청이 기준 변경, 화면 개선, 사용 가이드 보완 중 어디에 해당하는지 봅니다. |

| 실무자가 볼 항목 | 보는 이유 |
|---|---|
| 내 역할과 권한 | 볼 수 있는 정보와 할 수 있는 일을 구분합니다. |
| 판단 기록 | 중요한 승인, 반려, 예외 처리의 이유가 남는지 봅니다. |
| 기준 후보 | 반복적으로 유용한 판단이 기준 후보로 정리되는지 확인합니다. |
| 검토 상태 | 기준으로 반영되기 전 필요한 검토가 끝났는지 봅니다. |

운영 기록은 실무자를 평가하기 위한 자료가 아닙니다.
반복되는 판단을 개인 기억에만 맡기지 않고, 팀이 함께 확인할 수 있는 기준으로 정리하기 위한 장치입니다.

> [CAPTURE_PLACEHOLDER: Operations / access-audit-learning-summary / redacted]
>
> 넣을 화면: 접근 권한, 운영 기록, 기준 후보, 승인 상태가 한눈에 보이는 요약 화면.
>
> 제거할 민감정보: 사용자 이메일, 실제 이름, 계정 식별자, 원본 로그 값, 원본 요청/응답 세부값, 토큰, API key, 내부 시스템 세부 화면.

## 5. 실무자가 해야 하는 인터랙션

AdMate는 보기만 하는 화면이 아니라, 실무자의 확인과 판단을 남기는 흐름입니다.
다만 이 인터랙션은 캠페인을 자동 변경하기 위한 것이 아니라, 안전하게 확인하고 기록하기 위한 것입니다.

| 인터랙션 | 언제 하나요 | 남겨야 할 내용 | 주의할 점 |
|---|---|---|---|
| 확인 | 결과가 업무 맥락과 맞는지 볼 때 | 확인 여부, 필요한 경우 짧은 메모 | 확인은 자동 적용을 의미하지 않습니다. |
| 승인 | 제안된 조치나 기준 후보가 타당할 때 | 승인 이유, 적용 범위 | 권한이 있는 사용자만 수행합니다. |
| 반려 | 결과가 부정확하거나 적용하기 어려울 때 | 반려 이유, 보완이 필요한 부분 | 개인 비난이 아니라 기준 보완 관점으로 남깁니다. |
| 예외 설명 | 일반 기준과 다른 처리가 필요할 때 | 예외 사유, 기간, 적용 범위, 근거 | 예외가 곧 새 기준이 되는 것은 아닙니다. |
| 피드백 | 화면, 문구, 알림, 흐름이 불편할 때 | 어느 화면에서 무엇이 헷갈렸는지 | 민감 정보와 원본 캡처를 넣지 않습니다. |
| 기준 후보 제안 | 반복적으로 같은 판단이 필요할 때 | 어떤 조건에서 어떤 기준이 유용한지 | 검토 절차를 거친 뒤에만 기준으로 반영됩니다. |

좋은 인터랙션은 길 필요가 없습니다.
"어느 화면에서", "무엇을 확인했고", "왜 승인 또는 반려했는지" 정도만 남겨도 다음 기준을 만드는 데 도움이 됩니다.

## 6. 파일럿 권한과 역할

파일럿은 필요한 사람에게 필요한 범위만 열어 두는 방식으로 운영합니다.
신규 사용자는 최소 권한에서 시작하고, 더 넓은 권한은 승인 절차를 거쳐 조정합니다.

| 역할 | 파일럿에서의 의미 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| 선택 사용자 | 초기 파일럿에 초대된 실무자 | 배정된 화면을 사용하고, 실제 업무 흐름 기준으로 확인과 피드백을 남깁니다. | 전체 데이터 조회, 권한 변경, 승인 없는 기준 반영, 민감 데이터 업로드는 할 수 없습니다. |
| 리뷰어 | 특정 영역의 판단을 검토하도록 지정된 사용자 | 피드백과 기준 후보를 검토하고, 품질 확인 의견을 남깁니다. | 단독으로 전역 기준을 변경하거나 권한을 부여할 수 없습니다. |
| 관리자 | 파일럿 운영, 권한, 보안을 관리하는 사용자 | 접근 승인, 권한 관리, 예외 처리, 주요 기록 확인을 담당합니다. | 민감 정보를 문서나 캡처에 노출하거나 승인 없는 캠페인 변경을 할 수 없습니다. |

역할은 책임을 나누기 위한 장치입니다.
선택 사용자는 실제 업무에서 도움이 되는지 확인하고, 리뷰어는 기준으로 남겨도 되는 판단인지 한 번 더 보고, 관리자는 파일럿이 안전하게 운영되도록 권한과 기록을 관리합니다.

> 넣을 화면: 선택 사용자, 리뷰어, 관리자 역할과 접근 상태가 구분되어 보이는 화면.
>
> 제거할 민감정보: 실제 이름, 이메일, 사번, 계정 ID, 조직 내 상세 권한명, 인증 토큰, 세션 정보, 관리자 콘솔의 민감 화면.

## 7. 익명 피드백 보드

파일럿 중 불편한 점, 잘못 이해될 수 있는 문구, 실제 업무와 맞지 않는 흐름은 익명 피드백 보드에 남길 수 있습니다.
이 보드는 사람을 평가하기 위한 공간이 아니라, AdMate가 실무 흐름에 맞게 개선되어야 할 지점을 모으는 공간입니다.

| 남기면 좋은 내용 | 남기면 안 되는 내용 |
|---|---|
| 어디에서 막혔는지 | 특정 개인이나 팀을 지목하는 표현 |
| 어떤 표현이 불안했는지 | 광고주명, 브랜드명, 캠페인명, 계정명 |
| 어떤 확인이 줄면 좋은지 | 원본 캡처, 원본 URL, 원본 리포트 행 |
| 어떤 결과를 사람이 다시 봐야 했는지 | 비밀번호, 토큰, API key, 내부 인증 정보 |
| 어떤 판단을 기준 후보로 남기고 싶은지 | production 콘솔 민감 화면, 원본 API 응답 |

피드백은 짧아도 괜찮습니다.
"어느 화면에서", "무엇이 헷갈렸고", "어떻게 바뀌면 좋을지" 정도만 남겨도 파일럿 개선에 충분히 도움이 됩니다.

보드의 상세 사용법, 분류 태그, 처리 상태 확인 방식은 후속 파일럿 사용 가이드에서 안내합니다.

>
> 제거할 민감정보: 작성자 신원, 실제 고객명, 광고주명, 캠페인명, 계정명, 내부 캡처, 원본 URL, 원본 리포트 행, 개인정보.

## 8. 안전한 사용 원칙

AdMate를 안전하게 사용하기 위한 원칙은 두 가지입니다.
민감 정보는 그대로 넣지 않고, 최종 판단은 사람이 합니다.

| 민감 정보 유형 | 예시 |
|---|---|
| 고객 및 계정 정보 | 광고주명, 브랜드명, 계정명, 계정 ID, 담당자 이름, 이메일, 전화번호 |
| 캠페인 정보 | 실제 캠페인명, 원본 소재 URL, 내부 운영 URL, 원본 리포트 행 |
| 인증 정보 | 비밀번호, 토큰, API key, 쿠키, 세션, 환경 변수 값 |
| 원본 데이터 | 원본 엑셀 행, 원본 API 응답, production 콘솔의 민감 화면 |

| 원칙 | 실무에서의 의미 |
|---|---|
| 필요한 정보만 사용합니다. | 질문이나 피드백에는 상황을 요약하고 원본 데이터를 붙이지 않습니다. |
| 캡처는 공유 전 확인합니다. | 민감 정보가 보이는 화면은 문서나 보드에 올리지 않습니다. |
| AI 답변은 근거와 함께 봅니다. | 답변만 보지 않고 출처, 조건, 확인 필요 여부를 같이 봅니다. |
| 최종 판단은 사람이 합니다. | 자동 적용이나 자동 변경을 전제로 운영하지 않습니다. |
| 애매하면 멈추고 확인합니다. | 민감 정보 포함 여부나 적용 가능성이 헷갈리면 공유 전에 확인합니다. |

다음 표현은 파일럿 안내와 피드백에서 사용하지 않습니다.

| 피해야 할 표현 | 대신 사용할 표현 |
|---|---|
| AI가 알아서 판단합니다. | AdMate가 근거를 정리하고, 사람이 판단합니다. |
| 승인 없는 캠페인 수정 | 변경이 필요한 경우 승인 절차를 거쳐 사람이 적용합니다. |
| 모든 피드백이 자동 학습됩니다. | 승인된 검토 절차를 거친 피드백만 기준 후보가 됩니다. |
| 예측값이 성과를 보장합니다. | 예상 범위와 근거를 참고해 판단합니다. |

AdMate는 판단을 돕는 도구입니다.
정책 리스크, 고객 영향, 예산 변경, 캠페인 적용처럼 중요한 결정은 반드시 지정된 실무자와 승인 절차를 거쳐야 합니다.

## 9. 파일럿에서 함께 확인할 질문

파일럿 기간에는 기능을 많이 써보는 것보다 실제 업무에 맞는지 확인하는 것이 더 중요합니다.
다음 질문을 기준으로 사용 경험을 남겨 주세요.

| 질문 | 왜 확인하나요 |
|---|---|
| 어떤 반복 확인이 줄었나요? | 실제 시간을 줄이는 지점을 찾기 위해서입니다. |
| 어떤 결과는 사람이 다시 봐야 했나요? | 자동 확인과 사람 판단의 경계를 정하기 위해서입니다. |
| 어떤 표현이 오해를 만들 수 있나요? | 배포 전 문구와 화면을 더 안전하게 다듬기 위해서입니다. |
| 어떤 알림이 도움이 되었나요? | 꼭 필요한 신호와 부담스러운 신호를 구분하기 위해서입니다. |
| 어떤 정보를 더 보고 싶었나요? | 실무 판단에 필요한 근거를 보완하기 위해서입니다. |
| 어떤 정보는 보이면 안 된다고 느꼈나요? | 민감 정보 보호 기준을 더 안전하게 만들기 위해서입니다. |
| 어떤 판단을 다음 기준으로 남기면 좋을까요? | 개인 경험에만 남던 노하우를 팀의 운영 기준 후보로 정리하기 위해서입니다. |

이 질문에는 정답이 없습니다.
파일럿에서 나온 의견은 AdMate를 실제 업무에 맞는 도구로 다듬기 위한 재료입니다.
