# AdMate 파일럿 소개
## 반복 확인은 줄이고, 판단은 남깁니다

이 문서는 초기 파일럿에 참여하는 실무자를 위한 AdMate 소개서입니다.
AdMate는 사람을 대체하는 도구가 아닙니다.
캠페인 운영에서 반복적으로 발생하는 정책 확인, 세팅 검수, 캡처 준비, 성과 예측, 이상 감지의 부담을 줄이고, 실무자의 판단이 다음 운영 기준으로 정리될 수 있도록 돕는 업무 파트너입니다.

파일럿의 목적은 완성된 시스템을 한 번에 배포하는 것이 아니라, 실제 업무 흐름 안에서 어떤 확인이 줄어들 수 있는지, 어떤 화면과 문구가 더 안전해야 하는지, 어떤 판단을 운영 기준으로 남기면 좋은지 함께 확인하는 것입니다.

실제 화면 이미지는 추후 민감 정보가 제거된 캡처 또는 샘플 데이터 화면으로만 삽입합니다.
광고주명, 계정명, 캠페인명, 담당자 정보, 토큰, 원본 URL, 원본 리포트 행 등은 이 문서와 피드백에 포함하지 않습니다.

## 1. 한 페이지 요약

AdMate는 캠페인 운영 중 반복되는 확인 업무를 줄이고, 최종 판단은 실무자가 내릴 수 있도록 돕는 AI 기반 업무 도구입니다.

파일럿에서 확인할 핵심 흐름은 네 가지입니다.

| 영역 | 무엇을 돕나요 | 파일럿에서 확인할 점 |
|---|---|---|
| Compass | 광고 정책과 운영 가이드를 빠르게 찾고, 답변의 출처를 함께 확인합니다. | 답변이 실제 업무 질문에 충분히 도움이 되는지 확인합니다. |
| Sentinel | 캠페인 시작 전 세팅 차이를 확인하고, 운영 중 이상 신호를 먼저 보여줍니다. | 사전 검수와 운영 모니터링이 반복 확인을 줄이는지 봅니다. |
| Lens | 광고 캡처와 증빙 준비를 작업 목록으로 관리합니다. | 캡처 요청, 실패 확인, 재요청 흐름이 실무에 맞는지 봅니다. |
| Foresight | 예산, 기간, 타겟 조건에 따른 예상 성과를 범위와 근거로 확인합니다. | 기획 단계의 비교와 설명에 도움이 되는지 봅니다. |

파일럿 참여자는 단순 사용자가 아니라, AdMate가 실제 업무에 맞게 자리 잡을 수 있도록 판단 기준과 개선점을 함께 정리하는 사람입니다.
불편한 점이나 실제 업무와 맞지 않는 흐름은 익명 피드백 보드에 남길 수 있으며, 민감 정보는 포함하지 않습니다.

> [캡처 삽입 예정: AdMate 업무 흐름 요약]
>
> Compass, Sentinel, Lens, Foresight가 하나의 캠페인 운영 흐름 안에서 어떻게 연결되는지 보여주는 요약 화면을 넣습니다.
> 실제 광고주명, 캠페인명, 계정명은 보이지 않는 샘플 데이터 기준으로 구성합니다.

## 2. 왜 파일럿으로 시작하는가

캠페인 운영에는 늘 반복 확인이 따라옵니다.
정책이 바뀌었는지 확인하고, 매체 세팅이 미디어믹스와 맞는지 다시 보고, 캡처가 누락되지 않았는지 점검하고, 성과가 평소와 다른지 확인합니다.
이 과정은 중요하지만, 매번 사람이 처음부터 끝까지 확인하기에는 시간이 많이 들고 놓치기 쉬운 지점도 생깁니다.

AdMate 파일럿은 이 반복 확인을 한 번에 모두 없애겠다는 약속이 아닙니다.
먼저 실제 업무 흐름에 맞는 작은 범위에서 확인하고, 도움이 되는 부분과 더 다듬어야 할 부분을 분명히 나누기 위한 과정입니다.

파일럿을 통해 함께 확인하려는 질문은 다음과 같습니다.

| 질문 | 확인하려는 이유 |
|---|---|
| 어떤 확인 업무가 가장 반복적인가요? | 자동화보다 먼저 줄여야 할 부담을 정확히 찾기 위해서입니다. |
| 어떤 결과는 사람이 반드시 다시 봐야 하나요? | 최종 판단과 예외 승인의 경계를 분명히 하기 위해서입니다. |
| 어떤 표현이나 화면이 불안하게 느껴지나요? | 실제 배포 전에 오해와 불편을 줄이기 위해서입니다. |
| 어떤 판단을 다음 운영 기준으로 남기면 좋을까요? | 좋은 판단이 개인 경험에만 남지 않도록 하기 위해서입니다. |

> [캡처 삽입 예정: 파일럿 업무 흐름 개요]
>
> 정책 확인, 사전 검수, 운영 모니터링, 캡처, 성과 예측, 피드백이 이어지는 흐름을 한 화면에서 보여줍니다.
> 화면에는 실제 업무 데이터를 쓰지 않고, 익명화된 예시 캠페인만 표시합니다.

## 3. AdMate가 돕는 업무 흐름

AdMate는 캠페인의 특정 한 장면만 돕는 도구가 아니라, 기획 전 확인부터 운영 중 점검과 사후 기준 정리까지 이어지는 흐름을 돕습니다.

| 단계 | 실무자가 자주 하는 일 | AdMate가 돕는 방식 |
|---|---|---|
| 기획 전 | 정책과 운영 제한을 확인합니다. | Compass가 관련 정책과 출처를 함께 보여줍니다. |
| 캠페인 시작 전 | 미디어믹스와 매체 세팅을 대조합니다. | Sentinel이 차이와 확인 필요 항목을 정리합니다. |
| 운영 중 | 이상 신호, 변경 필요, 예외 상황을 확인합니다. | Sentinel이 상태를 요약하고 주의할 지점을 보여줍니다. |
| 증빙 준비 | 광고 캡처와 결과물을 정리합니다. | Lens가 캡처 요청과 작업 상태를 관리합니다. |
| 다음 제안 | 예산, 기간, 타겟별 예상 성과를 봅니다. | Foresight가 예측 범위와 근거를 함께 제시합니다. |
| 기준 정리 | 좋은 판단과 예외 처리 이유를 남깁니다. | 운영 기록과 기준 관리 영역에 승인된 기록을 남깁니다. |

중요한 점은 AdMate가 최종 결정을 대신하지 않는다는 것입니다.
AdMate는 먼저 확인하고, 실무자는 근거를 보고 판단하며, 필요한 경우 그 판단이 다음 운영 기준의 후보가 됩니다.

> [캡처 삽입 예정: 캠페인 생애주기 맵]
>
> 캠페인 기획, 정책 확인, 사전 검수, 운영 모니터링, 캡처, 성과 예측, 피드백이 순서대로 보이는 흐름도를 넣습니다.
> 각 단계에서 어느 제품 화면으로 이동하는지 간단히 표시합니다.

## 4. Compass: 정책 확인을 빠르게

Compass는 광고 정책, 운영 가이드, 내부 기준을 찾는 시간을 줄이기 위한 영역입니다.
실무자가 질문을 입력하면 관련 답변과 함께 출처, 근거 상태, 참고할 문서를 보여주는 방식으로 사용합니다.

예를 들어 다음과 같은 상황에서 도움이 됩니다.

| 상황 | Compass에서 확인할 수 있는 것 |
|---|---|
| 정책 문구가 기억나지 않을 때 | 관련 정책의 요약과 출처 문서를 확인합니다. |
| 특정 표현이 가능한지 헷갈릴 때 | 제한 기준, 예외 여부, 추가 확인이 필요한 항목을 봅니다. |
| 고객이나 내부 팀에 설명이 필요할 때 | 답변의 근거가 되는 문서와 문장 위치를 확인합니다. |

Compass의 답변은 참고와 확인을 돕기 위한 것입니다.
정책상 애매하거나 리스크가 있는 사안은 실무자의 확인과 승인 절차를 거쳐야 합니다.
답변만 보고 바로 적용하기보다, 출처와 근거 상태를 함께 보는 방식이 기본입니다.

> [캡처 삽입 예정: Compass 답변 및 출처 패널]
>
> 사용자가 광고 정책 질문을 입력하고, 답변 카드와 출처 패널이 함께 보이는 장면을 넣습니다.
> 출처 문서명과 근거 상태가 보이되, 실제 광고주명이나 내부 민감 문서는 노출하지 않습니다.

## 5. Sentinel: 세팅 사고를 막고 운영 이상을 감지

Sentinel은 캠페인 시작 전 세팅 검수와 운영 중 이상 감지를 돕는 영역입니다.
파일럿에서는 현재 운영 기준 화면을 중심으로 설명하며, 캠페인 시작 전에 확인해야 할 차이와 운영 중 주의해야 할 신호를 정리해 보여주는 데 초점을 둡니다.

Sentinel이 돕는 대표 업무는 다음과 같습니다.

| 업무 | Sentinel의 역할 |
|---|---|
| 시작 전 검수 | 미디어믹스와 매체 설정 사이의 차이, 누락, 확인 필요 항목을 보여줍니다. |
| 시작 가능 여부 확인 | 통과, 확인 필요, 보류처럼 현재 상태를 이해하기 쉬운 형태로 정리합니다. |
| 운영 중 모니터링 | 성과나 상태가 평소와 다른 지점을 먼저 보여줍니다. |
| 근거 확인 | 왜 확인이 필요한지 관련 근거와 요약을 함께 제공합니다. |

Sentinel은 캠페인을 임의로 수정하지 않습니다.
실제 적용, 예외 승인, 최종 판단은 지정된 실무자와 승인 절차를 통해 이루어집니다.
파일럿에서는 어떤 알림이 유용하고, 어떤 알림은 부담이 되는지 함께 확인합니다.

> [캡처 삽입 예정: Sentinel 사전 검수 워크벤치와 상태 패널]
>
> 미디어믹스 입력, 매체 설정 대조, 확인 필요 항목, 시작 가능 상태가 함께 보이는 화면을 넣습니다.
> 캠페인명과 계정명은 샘플 값으로 대체하고, 실제 매체 계정 정보나 원본 URL은 보이지 않게 처리합니다.

## 6. Lens: 캡처와 증빙을 정리

Lens는 광고 캡처와 증빙 준비를 작업 목록으로 관리하는 영역입니다.
운영 중 필요한 캡처를 요청하고, 진행 상태를 확인하며, 실패한 작업은 원인을 보고 다시 요청할 수 있도록 돕습니다.

캡처 업무는 단순해 보이지만 실제로는 반복 확인이 많습니다.
어떤 소재를 어떤 지면에서 캡처해야 하는지, 누락된 항목은 없는지, 실패한 캡처는 왜 실패했는지 확인해야 합니다.
Lens는 이 과정을 한곳에서 정리해 캡처 준비 부담을 줄이는 것을 목표로 합니다.

| Lens에서 볼 수 있는 것 | 설명 |
|---|---|
| 캡처 요청 | 필요한 소재, 지면, 형식에 맞춰 캡처 작업을 요청합니다. |
| 작업 목록 | 진행 중, 완료, 실패, 재요청 필요 상태를 확인합니다. |
| 실패 사유 | 캡처가 실패한 경우 원인과 다음 조치를 확인합니다. |
| 결과 확인 | 증빙에 사용할 수 있는 결과물을 확인합니다. |

캡처 결과에는 민감 정보가 들어갈 수 있으므로, 실제 배포용 문서나 피드백에는 원본 캡처를 그대로 올리지 않습니다.
필요한 경우 민감 정보를 제거한 화면만 사용합니다.

> [캡처 삽입 예정: Lens 캡처 워크벤치]
>
> 캡처 요청 생성, 작업 목록, 실패 또는 재요청 상태, 결과 확인 영역이 함께 보이는 화면을 넣습니다.
> 실제 브랜드명, 광고주명, 소재 URL, 계정 식별자는 샘플 값으로 대체합니다.

## 7. Foresight: 다음 캠페인의 예상 기준 보기

Foresight는 캠페인 기획 단계에서 예산, 기간, 타겟 조건에 따른 예상 성과를 확인하는 영역입니다.
하나의 확정 숫자를 알려주는 도구가 아니라, 비교 가능한 예측 범위와 근거를 함께 보여주는 방식으로 사용합니다.

예를 들어 예산 구간이 달라질 때 예상 도달이나 전환이 어떻게 달라질 수 있는지, 기간이나 타겟 조건이 바뀔 때 어느 정도 차이가 날 수 있는지 볼 수 있습니다.
이 결과는 제안서나 내부 논의에서 참고할 수 있지만, 실제 성과를 보장하는 값은 아닙니다.

| 확인 항목 | 보는 방법 |
|---|---|
| 입력 조건 | 예산, 기간, 타겟, 목표 KPI를 확인합니다. |
| 예측 결과 | 단일 숫자보다 범위와 변화 방향을 봅니다. |
| 근거 상태 | 어떤 데이터와 조건을 바탕으로 한 예측인지 확인합니다. |
| 비교 | 여러 조건을 나란히 두고 차이를 봅니다. |

Foresight는 더 나은 질문과 비교를 돕는 도구입니다.
최종 제안과 운영 판단은 실무자가 맥락을 보고 결정합니다.

> [캡처 삽입 예정: Foresight 성과 예측 시뮬레이터]
>
> 예산, 기간, 타겟 조건을 입력한 뒤 예상 성과 범위와 근거 카드가 표시되는 장면을 넣습니다.
> 실제 고객 데이터나 원본 리포트 행은 표시하지 않고, 집계 또는 샘플 데이터 기준으로 구성합니다.

## 8. 운영 기록과 기준 관리 영역

AdMate에는 실무자의 판단, 승인, 예외 처리, 피드백을 안전하게 기록하고 관리하는 공통 영역이 있습니다.
이 영역은 화면마다 흩어진 판단을 다음 운영 기준의 후보로 정리하기 위한 기반입니다.

여기서 중요한 원칙은 모든 행동이 자동으로 학습되거나 기준으로 반영되지 않는다는 점입니다.
좋은 판단이나 반복적으로 필요한 기준은 승인된 검토 절차를 거쳐야 하며, 누가 어떤 이유로 판단했는지 필요한 범위에서만 기록됩니다.

| 관리되는 항목 | 의미 |
|---|---|
| 운영 기록 | 사용 중 발생한 확인, 승인, 반려, 예외 처리 이력을 남깁니다. |
| 권한 상태 | 사용자가 어떤 범위까지 볼 수 있고 처리할 수 있는지 관리합니다. |
| 기준 후보 | 반복적으로 유용한 판단을 다음 운영 기준 후보로 정리합니다. |
| 감사 기록 | 중요한 변경과 승인 흐름을 확인할 수 있게 남깁니다. |

이 영역은 실무자를 평가하기 위한 공간이 아닙니다.
반복되는 판단을 개인 기억에만 맡기지 않고, 팀이 함께 확인할 수 있는 기준으로 정리하기 위한 장치입니다.

> [캡처 삽입 예정: 운영 기록과 권한 요약 화면]
>
> 접근 권한, 운영 기록, 기준 후보, 승인 상태가 한눈에 보이는 요약 화면을 넣습니다.
> 사용자 이메일, 계정 식별자, 원본 로그 값은 노출하지 않고 역할과 상태 중심으로 표시합니다.

## 9. 파일럿 참여자의 역할: 선택 사용자, 리뷰어, 관리자

파일럿에서는 모든 사람이 같은 권한으로 시작하지 않습니다.
각자의 역할에 따라 볼 수 있는 범위와 할 수 있는 일이 다릅니다.
기본 원칙은 필요한 사람에게 필요한 범위만 열어 두는 것입니다.

| 역할 | 파일럿에서의 의미 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| 선택 사용자 | 초기 파일럿에 초대된 실무자 | 배정된 화면을 사용하고, 업무 흐름과 피드백을 남깁니다. | 전체 데이터 조회, 권한 변경, 승인 없는 기준 반영은 할 수 없습니다. |
| 리뷰어 | 특정 영역의 판단을 검토하도록 지정된 사용자 | 피드백과 기준 후보를 검토하고, 품질 확인 의견을 남깁니다. | 단독으로 전역 기준을 바꾸거나 권한을 부여할 수 없습니다. |
| 관리자 | 파일럿 운영과 권한, 보안을 관리하는 사용자 | 접근 승인, 권한 관리, 예외 처리, 기록 확인을 담당합니다. | 민감 정보를 문서나 캡처에 노출하거나 승인 없는 자동 변경을 할 수 없습니다. |

신규 사용자는 최소 권한에서 시작합니다.
권한이 더 필요한 경우에는 별도 승인 절차를 통해 조정합니다.
역할은 편의를 위한 구분이 아니라, 파일럿을 안전하게 운영하기 위한 기본 장치입니다.

> [캡처 삽입 예정: 사용자 역할과 접근 상태 화면]
>
> 선택 사용자, 리뷰어, 관리자 역할과 접근 상태가 구분되어 보이는 화면을 넣습니다.
> 실제 이름과 이메일 대신 역할명과 샘플 사용자로 표시합니다.

## 10. 익명 피드백 보드

파일럿 중 불편한 점, 잘못 이해될 수 있는 문구, 실제 업무와 맞지 않는 흐름은 익명 피드백 보드에 남길 수 있습니다.
이 보드는 사람을 평가하기 위한 공간이 아니라, AdMate가 실무 흐름에 맞게 개선되어야 할 지점을 모으는 공간입니다.

피드백은 다음처럼 남겨 주세요.

| 권장 | 피해야 할 것 |
|---|---|
| 어디에서 막혔는지 요약합니다. | 특정 개인이나 팀을 지목하지 않습니다. |
| 어떤 표현이 불안했는지 적습니다. | 광고주명, 캠페인명, 계정명을 그대로 쓰지 않습니다. |
| 어떤 확인이 줄면 좋을지 제안합니다. | 원본 캡처, 원본 URL, 리포트 행을 올리지 않습니다. |

보드의 상세 사용법, 분류 태그, 처리 상태 확인 방식은 후속 사용 가이드에서 안내합니다.

> [캡처 삽입 예정: 익명 피드백 보드]
>
> 피드백 제목, 상황 요약, 개선 제안, 처리 상태가 보이는 보드 화면을 넣습니다.
> 작성자 신원, 실제 고객명, 내부 캡처가 보이지 않는 형태로 구성합니다.

## 11. 안전하게 사용하기: 민감 정보와 최종 판단 원칙

AdMate를 안전하게 사용하려면 두 가지 원칙을 지켜야 합니다.
첫째, 민감 정보는 문서, 캡처, 피드백, 외부 도구 입력에 그대로 넣지 않습니다.
둘째, 최종 판단과 예외 승인은 사람의 역할로 남깁니다.

민감 정보에는 다음이 포함됩니다.

| 유형 | 예시 |
|---|---|
| 고객 및 계정 정보 | 광고주명, 브랜드명, 계정명, 계정 ID, 담당자 이름, 이메일, 전화번호 |
| 캠페인 정보 | 실제 캠페인명, 원본 소재 URL, 내부 운영 URL, 원본 리포트 행 |
| 인증 정보 | 비밀번호, 토큰, API key, 쿠키, 세션, 환경 변수 값 |
| 원본 데이터 | 원본 엑셀 행, 원본 API 응답, production 콘솔의 민감 화면 |

다음 원칙을 파일럿 중 계속 지켜 주세요.

| 원칙 | 실무에서의 의미 |
|---|---|
| 필요한 정보만 사용합니다. | 질문이나 피드백에는 상황을 요약하고, 원본 데이터를 붙이지 않습니다. |
| 캡처는 확인 후 공유합니다. | 민감 정보가 보이는 화면은 문서나 보드에 올리지 않습니다. |
| AI 답변은 근거와 함께 봅니다. | 답변만 보지 않고 출처, 조건, 확인 필요 여부를 같이 봅니다. |
| 최종 판단은 사람이 합니다. | 자동 적용이나 자동 변경을 전제로 운영하지 않습니다. |
| 애매하면 멈추고 확인합니다. | 민감 정보 포함 여부나 적용 가능성이 헷갈리면 공유 전에 확인합니다. |

AdMate는 판단을 돕는 도구입니다.
정책 리스크, 고객 영향, 예산 변경, 캠페인 적용처럼 중요한 결정은 반드시 지정된 실무자와 승인 절차를 거쳐야 합니다.

## 12. 함께 확인할 질문들

파일럿 기간에는 기능을 많이 써보는 것보다 실제 업무에 맞는지 확인하는 것이 더 중요합니다.
다음 질문을 기준으로 사용 경험을 남겨 주세요.

| 질문 | 왜 중요한가요 |
|---|---|
| 어떤 반복 확인이 줄었나요? | 실제 시간을 줄이는 지점을 찾기 위해서입니다. |
| 어떤 결과는 다시 확인해야 했나요? | 사람이 판단해야 할 경계를 정하기 위해서입니다. |
| 어떤 표현이 오해를 만들 수 있나요? | 배포 전 문구와 화면을 다듬기 위해서입니다. |
| 어떤 알림이 도움이 되었나요? | 꼭 필요한 신호와 부담스러운 신호를 구분하기 위해서입니다. |
| 어떤 정보를 더 보고 싶었나요? | 실무 판단에 필요한 근거를 보완하기 위해서입니다. |
| 어떤 정보는 보이면 안 된다고 느꼈나요? | 민감 정보 보호 기준을 더 안전하게 만들기 위해서입니다. |

이 질문에 대한 답은 정답을 찾기 위한 것이 아닙니다.
실제 업무에 맞는 도구로 다듬기 위한 재료입니다.
