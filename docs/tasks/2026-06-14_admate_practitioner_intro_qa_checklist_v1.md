## 3. QA 판정 체계

| 판정 | 의미 | 조치 |
|---|---|---|
| Pass | 최종본 배포 기준을 만족한다. | 승인 가능 |
| Conditional Pass | 문서 방향은 맞지만 문구 보완 또는 캡처 교체 전제 조건이 있다. | 수정 후 재확인 |
| Reject | 보안, 권한, 제품 경계, 사람 대체 오해 중 하나라도 중대한 문제가 있다. | 최종본 승인 불가 |

| 심각도 | 기준 |
|---|---|
| P0 | 민감 정보 노출, 자동 변경/자동 판단 오해, Sentinel legacy 기준 설명, 승인 없는 학습 반영처럼 즉시 리젝해야 하는 문제 |
| P1 | 실무자에게 불안이나 오해를 줄 수 있는 문장, 내부 엔진명 과잉 노출, 권한 설명 미흡 |
| P2 | 톤, 구조, 캡처 placeholder 표기, 후속 가이드 분리처럼 승인 전 정리해야 하는 품질 문제 |

## 4. QA 체크리스트

### 4.1 민감 정보와 보안 금지 표현

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| 광고주, 브랜드, 계정, 캠페인 식별 정보 | 본문, 표, 예시, 캡처 placeholder에 실제 광고주명, 브랜드명, 계정명, 캠페인명이 없다. | 실제 고객, 계정, 캠페인을 식별할 수 있는 값이 보인다. | P0 |
| 개인 정보와 연락처 | 담당자 이름, 이메일, 전화번호, 사용자 ID는 샘플 또는 역할명으로 대체되어 있다. | 실제 개인 식별 정보가 문서나 캡처 설명에 남아 있다. | P0 |
| 인증 정보 | 토큰, API key, service role key, cookie, session, credential, env 값이 없다. | 키 값, 토큰 일부, env prefix, credential 예시가 노출된다. | P0 |
| 원본 데이터 | 원본 엑셀 행, 원본 리포트 행, 원본 API 응답, production 콘솔 원본 화면을 넣지 않는다. | "원본 데이터를 그대로 붙여 넣어 분석"하거나 원본 행/응답 캡처를 쓰도록 안내한다. | P0 |
| LLM 전달 | 외부 LLM/API에는 익명화, 집계, 요약 데이터만 전달한다는 원칙이 유지된다. | raw campaign-level 데이터나 고객 식별 데이터를 LLM에 직접 보낸다고 설명한다. | P0 |
| 오류와 로그 | 보안 오류, 인증 오류, provider 오류의 내부 세부 원인을 사용자 화면에 노출하지 않는다는 원칙이 있다. | 내부 키, provider 응답, DB 오류, 인증 실패 원인을 그대로 노출하는 예시가 있다. | P1 |

검토 메모:

- "실제 화면", "원본 리포트", "운영 데이터"라는 표현은 반드시 `redacted`, `synthetic`, `샘플`, `익명화`, `집계` 중 하나와 함께 쓰였는지 확인한다.
- 캡처 후보가 들어오는 순간 본 체크리스트와 별도 화면 QA를 다시 수행한다.

### 4.2 사람 대체, 자동 판단, 자동 변경 오해 표현

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| 사람 대체 표현 | "사람을 대체하지 않는다", "반복 확인을 줄인다", "실무자가 판단한다"는 메시지가 유지된다. | "사람 없이 운영", "실무자를 대체", "담당자 없이 판단"처럼 읽힌다. | P0 |
| 자동 판단 표현 | AI 답변은 참고와 확인을 돕고, 애매한 사안은 사람이 확인한다고 설명한다. | "AI가 알아서 판단", "정책 리스크를 자동 확정"처럼 최종 판단 주체가 AI로 읽힌다. | P0 |
| 자동 변경 표현 | 캠페인 적용, 예산 변경, 설정 변경, 예외 승인은 사람과 승인 절차를 거친다고 설명한다. | "캠페인을 자동으로 수정", "승인 없이 적용", "AI가 바로 반영"으로 읽힌다. | P0 |
| 학습 반영 표현 | 판단은 승인된 검토 절차를 거쳐 운영 기준 후보가 된다고 설명한다. | 모든 사용자 행동이나 피드백이 자동으로 Hermes 학습에 반영된다고 설명한다. | P0 |
| 예측 결과 표현 | Foresight 결과는 보장값이 아니라 범위와 근거가 있는 참고값으로 설명한다. | 예측값이 실제 성과를 보장하거나 확정하는 것처럼 말한다. | P1 |

권장 표현:

- "AdMate는 먼저 확인하고, 실무자는 근거를 보고 판단합니다."
- "좋은 판단은 승인된 검토 절차를 거쳐 다음 운영 기준 후보가 됩니다."
- "자동 적용이나 자동 변경을 전제로 운영하지 않습니다."

금지 표현:

- "AI가 알아서 운영합니다."
- "실무자 판단을 자동으로 대체합니다."
- "캠페인 설정을 자동으로 수정합니다."
- "모든 행동이 학습됩니다."

### 4.3 Sentinel legacy 언급 금지와 현재 Core 기준 설명

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| Sentinel 기준 | Sentinel은 `admate-agent-core`의 현재 Core-native Sentinel surface 기준으로 설명한다. | `admate-sentinel-legacy`를 현재 제품 기준 또는 사용자용 기준처럼 설명한다. | P0 |
| Legacy 명칭 | 최종 실무자용 본문에는 Sentinel legacy repo명이나 legacy 구현 세부를 노출하지 않는다. | "legacy Sentinel", "구버전 repo", legacy route 등을 본문에 넣는다. | P0 |
| Sentinel 역할 | pre-launch 상태, launch gate, 운영 롤업, live monitoring, operator action을 실무자용 언어로 설명한다. | Sentinel을 단순 과거 검수 도구로 축소하거나 현재 Core 권한/기록 기준과 분리해 설명한다. | P1 |
| 자동 수정 경계 | Sentinel은 차이, 확인 필요 항목, 이상 신호를 보여주며 임의 수정하지 않는다고 설명한다. | Sentinel이 캠페인을 직접 바꾸는 것처럼 설명한다. | P0 |

검토 메모:

- 내부 검토용 근거 문서에서는 legacy를 도메인 원형으로 참조할 수 있으나, 실무자 소개 최종본에는 노출하지 않는다.
- 최종본의 Sentinel 섹션 제목과 본문은 "현재 운영 기준 화면" 또는 "현재 Core 기준"의 의미가 드러나야 한다.

### 4.4 내부 엔진명 과잉 노출 금지

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| Openclaw | 실무자 소개 본문에서는 필요할 때만 "실행/자동화/외부 시스템 연결 기반" 정도로 풀어쓴다. | Openclaw를 제품명처럼 반복 노출하거나 내부 구조를 상세 설명한다. | P1 |
| Hermes | "학습/기준 관리" 수준으로만 설명하고, 학습 권한과 승인 절차를 함께 둔다. | Hermes learning이 모든 피드백을 자동 흡수하는 것처럼 설명한다. | P0 |
| Agent Core | 실무자에게는 "운영 기록과 권한, 기준 관리 영역"처럼 이해 가능한 표현을 우선 사용한다. | Core 내부 route, DB, runtime, orchestration 세부를 소개 문서에 과도하게 넣는다. | P1 |
| 기술 스택 | Next.js, Supabase, pgvector, Puppeteer, FastAPI 등은 실무자 소개 최종본에서 원칙적으로 제외한다. | 기술 스택 설명이 소개 문서의 주요 메시지를 밀어낸다. | P2 |

권장 방식:

- 제품군 이름은 Compass, Sentinel, Lens, Foresight 중심으로 설명한다.
- 내부 엔진명은 관리자용 또는 후속 운영 가이드로 넘긴다.
- "권한, 기록, 감사, 승인된 기준 관리"처럼 실무자가 알아야 하는 결과 중심 언어를 사용한다.

### 4.5 캡처 placeholder 유지와 실제 캡처 미삽입

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| placeholder 형식 | 모든 화면 위치는 placeholder로 표시되어 있고 실제 이미지 파일은 삽입하지 않는다. | 최종 QA 전 실제 캡처, 링크, 이미지 파일, base64 이미지가 들어간다. | P0 |
| placeholder 설명 | 각 placeholder에 보여줄 장면, 보이지 않아야 할 민감 정보, 샘플/익명화 조건이 적혀 있다. | 캡처 위치만 있고 redaction 기준이 없다. | P1 |
| 캡처 범위 | Compass, Sentinel, Lens, Foresight, 운영 기록/권한 영역의 캡처 목적이 문장과 일치한다. | 제품 설명과 맞지 않는 화면 또는 내부 관리자 화면을 넣도록 되어 있다. | P1 |
| 후속 QA | 실제 캡처 삽입은 캡처 수집, redaction, 데스크톱/모바일 화면 QA 이후로 보류되어 있다. | "추후 교체" 조건 없이 캡처 삽입을 완료 상태로 표시한다. | P0 |

최종본에서 허용되는 표기 예:

```text
[CAPTURE_PLACEHOLDER: Compass / answer-source-panel / redacted]
[CAPTURE_PLACEHOLDER: Sentinel / prelaunch-workbench / redacted]
[CAPTURE_PLACEHOLDER: Lens / capture-workbench / redacted]
[CAPTURE_PLACEHOLDER: Foresight / simulator-result / redacted]
[CAPTURE_PLACEHOLDER: Agent Core / access-audit-learning / redacted]
```

### 4.6 실무자용 문체와 과장 금지

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|

| 현재 가능 범위 | 현재 가능한 것과 후속 사용 가이드로 넘길 것을 구분한다. | 아직 확정되지 않은 기능을 이미 제공되는 것처럼 말한다. | P0 |
| 문장 톤 | 동료에게 설명하듯 차분하고 구체적이다. | 마케팅 카피, 임원 보고 문구, 성과 보장 표현이 과하다. | P2 |
| 상세 사용법 분리 | 클릭 순서, 예외 처리 SOP, 제품별 세부 절차는 후속 가이드로 둔다. | 소개 문서가 사용 매뉴얼 수준으로 길어져 핵심 메시지가 흐려진다. | P2 |

검토 질문:

- 이 문장은 파일럿 실무자가 "내 업무에서 무엇이 달라지는지" 이해하는 데 도움이 되는가?
- 이 문장이 "AI가 나를 평가하거나 대체한다"는 불안을 만들지는 않는가?
- 이 기능은 현재 제공되는 것인가, 후속 가이드 또는 보류 항목인가?

### 4.7 익명 피드백 보드 목적

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| 목적 | 익명 피드백 보드는 제품 개선과 업무 흐름 개선을 위한 공간으로 설명한다. | 개인 평가, 인사 평가, 책임 추궁, 실수 지적 공간처럼 읽힌다. | P0 |
| 익명성 | 이름을 밝히지 않아도 문제와 개선점을 남길 수 있다고 설명한다. | 작성자를 추적하거나 개인별 성과를 비교할 수 있다는 암시가 있다. | P0 |
| 비난 금지 | 특정 개인이나 팀을 지목하지 말고 상황 중심으로 남기도록 안내한다. | 특정 담당자나 팀의 실수를 기록하도록 유도한다. | P1 |
| 민감 정보 금지 | 광고주명, 캠페인명, 계정명, 원본 URL, 내부 캡처를 올리지 말라고 안내한다. | 피드백에 원본 캡처나 고객 정보를 첨부하도록 안내한다. | P0 |
| 후속 분리 | 보드 사용법, 태그, 처리 상태, 응답 기준은 후속 사용 가이드로 분리한다. | 소개 문서에서 상세 운영 정책을 확정한 것처럼 과도하게 설명한다. | P2 |

권장 핵심 문장:

```text
이 보드는 사람을 평가하기 위한 공간이 아니라, AdMate가 실무 흐름에 맞게 개선되어야 할 지점을 모으는 공간입니다.
```

### 4.8 권한, 리뷰어, 관리자 설명의 안전성

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| 최소 권한 | 신규 사용자는 기본적으로 필요한 범위만 볼 수 있다고 설명한다. | 파일럿 사용자가 전체 데이터나 전체 기능에 접근할 수 있는 것처럼 설명한다. | P0 |
| 역할 구분 | 선택 사용자, 리뷰어, 관리자의 역할과 할 수 없는 일이 구분되어 있다. | 역할 간 권한 경계가 없거나 누구나 승인/권한 변경을 할 수 있는 것처럼 보인다. | P0 |
| 리뷰어 권한 | 리뷰어는 기준 후보와 피드백을 검토하지만 단독 전역 기준 변경은 하지 않는다고 설명한다. | 리뷰어가 전사 기준을 단독 변경하거나 승인 없이 학습 반영할 수 있는 것처럼 보인다. | P0 |
| 관리자 권한 | 관리자는 접근 승인, 권한 관리, 예외 처리, 기록 확인을 담당하되 민감 정보 노출과 승인 없는 자동 변경은 금지된다. | 관리자가 토큰 공유, 민감 정보 노출, 승인 없는 변경을 할 수 있는 것처럼 읽힌다. | P0 |
| 기록과 감사 | 권한 변경, 승인, 반려, 학습 반영은 audit/operator 기록 대상임을 설명한다. | 중요한 변경과 승인이 기록되지 않는 것처럼 보인다. | P1 |
| 학습 권한 | Hermes 학습 영향 권한은 별도 승인된 사용자에게만 있다고 설명한다. | 일반 사용자의 모든 행동이 곧바로 기준과 학습에 반영된다고 설명한다. | P0 |

검토 메모:

- "할 수 있는 일"과 "할 수 없는 일"을 같이 보여주는 표는 유지하는 것이 안전하다.
- 권한은 편의 기능이 아니라 파일럿 보안 장치로 설명해야 한다.

### 4.9 최종 승인 기준과 남은 보류 항목

| 확인 항목 | 통과 기준 | 리젝 기준 | 심각도 |
|---|---|---|---|
| 최종 승인 기준 | 보안, 표현, 권한, 캡처, 제품 경계, 톤 기준이 모두 Pass 또는 승인 가능한 Conditional Pass다. | P0 항목이 하나라도 남아 있다. | P0 |
| 보류 항목 표시 | 실제 캡처 삽입, 익명 피드백 보드 상세 사용법, 캠페인 자동 변경, 임원 보고용 ROI/로드맵은 보류 또는 후속 문서로 분리되어 있다. | 보류 항목을 이번 소개 문서에서 확정 기능처럼 설명한다. | P0 |
| 후속 작업 큐 | 캡처 수집, 화면 QA, 제품별 사용 가이드, 최종 문서 제작의 남은 작업이 명확하다. | 남은 작업이 빠져 있어 최종본이 배포 준비 완료로 오해된다. | P1 |
| 배포 범위 | 초기 파일럿 대상 특정 팀 및 소수 실무자용이라는 범위가 유지된다. | 전체 임직원 공개 또는 외부 배포 문서처럼 작성되어 있다. | P1 |

보류 상태로 남겨야 하는 항목:

- 실제 플랫폼 캡처 삽입
- 익명 피드백 보드 상세 사용법
- 캠페인 자동 변경 또는 mutation 안내
- 임원 보고용 ROI, 투자 효과, 장기 로드맵
- 제품별 클릭 순서와 상세 운영 SOP

## 5. 최종본 QA 절차

1. 본문 전체에서 P0 금지 표현과 민감 정보 노출을 먼저 검색한다.
2. 각 제품 섹션이 기준 자료의 제품 경계와 맞는지 확인한다.
3. Sentinel 섹션이 현재 `admate-agent-core` 기준이며 legacy 언급이 없는지 확인한다.
4. 내부 엔진명, route, DB, runtime, 기술 스택이 실무자용 범위를 넘지 않는지 확인한다.
5. 모든 캡처 위치가 placeholder이고 실제 캡처가 삽입되지 않았는지 확인한다.
6. 선택 사용자, 리뷰어, 관리자 표에서 권한과 금지 행위가 함께 설명되는지 확인한다.
7. 익명 피드백 보드가 개인 평가가 아니라 제품 개선 채널로 설명되는지 확인한다.
8. 다음 단계와 보류 항목이 최종본 말미에 남아 있는지 확인한다.
9. P0 0건, P1 해결 또는 명시적 보류, P2 배포 전 정리 완료 상태인지 확인한다.

## 7. 최종본 승인 전 필수 수정 기준

최종본 승인 전 아래 항목 중 하나라도 해당하면 승인하지 않는다.

| 필수 수정 기준 | 리젝 조건 |
|---|---|
| 민감 정보 노출 0건 | 광고주명, 계정명, 캠페인명, 이메일, URL, 토큰, 원본 리포트 행, 원본 API 응답, production 콘솔 민감 화면이 하나라도 보이면 Reject |
| 사람 최종 판단 원칙 | AI가 사람을 대체하거나 최종 판단, 예외 승인, 캠페인 변경을 자동 수행하는 것처럼 읽히면 Reject |
| 승인 없는 자동 변경 금지 | 캠페인 세팅, 예산, 운영 상태가 승인 없이 자동 변경된다고 설명하면 Reject |
| Sentinel 현재 기준 | Sentinel을 legacy 기준으로 설명하거나 legacy repo/구현명을 실무자용 본문에 노출하면 Reject |
| 내부 엔진명 최소화 | Openclaw, Hermes, route, DB, runtime 설명이 실무자 이해에 필요한 범위를 넘으면 수정 전 승인 보류 |
| 실제 캡처 미삽입 | redaction과 화면 QA 전 실제 캡처가 들어가 있으면 Reject |
| 익명 피드백 목적 | 익명 피드백 보드가 개인 평가, 인사 평가, 책임 추궁으로 읽히면 Reject |
| 권한 안전성 | 선택 사용자, 리뷰어, 관리자 권한 경계가 불명확하거나 누구나 권한 변경/학습 반영/전역 기준 변경을 할 수 있는 것처럼 보이면 Reject |
| 보류 항목 유지 | 실제 캡처, 상세 사용법, 자동 변경, 임원 보고용 ROI/로드맵이 이번 소개 문서의 확정 범위처럼 들어가면 Reject |

최종 승인 가능 조건은 다음과 같다.

- P0 항목이 0건이다.
- P1 항목은 모두 수정되었거나, 커맨더가 명시적으로 보류 승인한 상태다.
- 캡처는 placeholder만 있고 실제 이미지는 없다.
- 문서의 첫 메시지가 "AdMate는 사람을 대체하지 않고 반복 확인을 줄이며 실무자의 판단을 기준으로 남기도록 돕는다"로 유지된다.
- 남은 작업은 캡처 수집, 캡처 QA, 제품별 사용 가이드, 최종 제작 단계로 분리되어 있다.
